# skyPaws-universe · 项目方向与架构讨论

> 记录时间：2026-11-01
> 状态：方向讨论已收敛，尚未动工。本文档是共识的"钉子"——后续有新决策时追加记录，不覆盖。

## 0. 一句话愿景

一个属于个人的万能 agent 助手：大脑住在自己的电脑上，任何设备都是它的窗口；能力靠接入工具无限生长；先让它学会写代码——然后用它来养大它自己。

## 1. 原始愿景（原话摘录）

> 这个项目就相当于我一个 agent 助手，有万能（这个万能体现在后续可以随意接入工具实现万能）。首先这个项目最重要是万物互联（意思是说，可以任何设备都可以使用它），然后显示首先实现桌面端和移动端，然后需要有丰富交互（人与 LLM 交互，文字、语音），想把科幻科技实现。然后现在我想到的功能有：agent 编辑器（参考 Cursor、Claude Code、Codex 等，这个是目前最主要的，因为有这个我才能实现代码，并且实现多端最好，这样子我可以方便操作代码）、多媒体功能（音乐、电影、视频）、交互（文字、视频）、控制（可以控制我赋予权限的设备，例如电脑、手机、手表等）。

## 2. 架构总判断

**起点不是编辑器，而是 agent 内核。** Cursor / Claude Code / Codex 的本体是引擎：模型调用循环（流式、工具调用、上下文管理）+ 工具协议 + 会话与权限。界面只是引擎的壳。内核先行的好处：

1. 最快进入"用它造它自己"的自举循环；
2. 内核与 UI 无关，CLI / 桌面 / 手机复用同一内核，一行不浪费。

**"万能 + 万物互联"拆开是两个抽象：**

| 抽象 | 对应愿景 | 说明 |
|---|---|---|
| 工具层（MCP 协议） | 万能 | 任何能力都做成工具 / MCP server 接入；不自造协议，直接复用生态 |
| 一个大脑 + 多个壳 | 万物互联 | agent host 持有会话、记忆、配置；桌面、手机、CLI、手表都是瘦客户端；会话是跨设备的原子 |

功能映射：

| 愿景功能 | 本质 |
|---|---|
| agent 编辑器 | 内核 + 代码类工具（read/write/edit/glob/grep/shell）+ 桌面编辑器界面 |
| 多媒体（音乐/电影/视频） | 媒体库工具 + 播放界面 |
| 交互（文字/语音/视频） | 同一会话的不同输入输出通道：语音 = STT → 同一循环 → TTS |
| 控制设备 | 设备节点把自身能力暴露为带权限的工具 + 权限系统 |

## 3. 已定决策（2026-11-01）

| # | 决策 | 内容 |
|---|---|---|
| D1 | 大脑住哪 | **本地 host**，跑在用户电脑上。会话、记忆、配置由 host 持有，设备只是窗口。多设备互通 = 加客户端，不改架构 |
| D2 | 编辑器定位 | **自我更新的驾驶舱**，不是 IDE 产品，不对标 Cursor 功能 |
| D3 | 交互顺序 | 文字先行 → 轮次式语音（按住说话、一来一回）→ 全双工/视频远期 |
| D4 | 设备优先级 | 桌面（电脑）优先，先让 agent 出生；移动端随后 |
| D5 | 安全底座 | git 从第一天存在；agent 在分支上干活、人审 diff 后合并；权限门禁是一等公民 |
| D6 | 出生形态 | **终端 agent（内核 + CLI）先行**（2026-11-01 定）：自我更新只需要"能改文件的 agent"，终端就是它的手脚；编辑器界面（M1）是随后的驾驶舱，不是自举的前提 |

### D2 的推论：编辑器砍小一半

自我更新只需要四个面板：**对话、diff 视图、文件树、终端**。不需要代码补全、inline edit 等 Cursor 级功能；v1 甚至可以没有完整的代码编辑窗格——它写代码、人审 diff，偶尔手改就调系统编辑器。等用顺了再决定要不要长出编辑器面板。

### D5 的推论：自举安全约定

- 动工第一步 `git init`（当前目录还不是 git 仓库）；
- agent 永远在分支上干活，人审后合并；
- 写文件、跑命令走确认或白名单，agent 没有能力一次性搞坏自己。

## 4. 记忆系统 v1

多设备互通的底座是"状态住在 host 上"，记忆是其中最值钱的部分。v1 两层，刻意朴素：

1. **会话持久化**：每段对话落盘在 host，换设备续上的就是它；
2. **记忆卡**：会话结束（或周期性）让模型把"值得长期记住的事"写成小卡片——偏好、项目事实、做过的决定；下个会话开始时按相关度注入上下文。

向量检索、遗忘机制、重要性评分等，等卡片多到找不过来再加。

## 5. "出生"蓝图（M0）

四个包（pnpm monorepo）：

```
packages/
  kernel    agent 循环、流式、工具调用、会话、权限、模型适配层（OpenAI 兼容，GLM 先跑通）
  tools     read / write / edit / glob / grep / shell，带权限门禁；
            上一版 core 的 read 设计（预算截断、错误是教程、能力表）直接作为规格继承
  cli       第一具身体：终端对话
apps/
  desktop   Tauri 2 + React：从聊天窗开始，长出四面板
```

**出生证明（M0 完成标准）：**

- [ ] 能在电脑上用文字与它对话
- [ ] 它能读写本仓库、跑命令
- [ ] 它的每个动作有 git 与权限兜底
- [ ] 让它自己开分支，给自己加上第一个小功能

做到这一刻，agent 算"出生"，之后是它和人一起养大它。

**出生形态（2026-11-01 已定，见 D6）**：终端 agent 先行。理由：自我更新只需要"能改文件的 agent"——终端就是它的手脚（ZCode / Claude Code 本身就是这种形态）；编辑器界面是 M1 的舒适驾驶舱，不是自举的前提。

实施细化见：[2026-11-01-第一阶段-M0-计划与最终成果.md](./2026-11-01-第一阶段-M0-计划与最终成果.md)。

## 6. 里程碑路线（每步都产出能用的东西）

| 里程碑 | 内容 | 产物 |
|---|---|---|
| M0 | 内核 + CLI | 终端可用的编码 agent（出生） |
| M1 | 桌面端 | Tauri + React：对话 / diff / 文件树 / 终端 → 自我更新驾驶舱 |
| M2 | 万物互联 | 内核抽成常驻 host；移动端 / 网页端接入；会话跨端同步 |
| M3 | 设备控制 | 电脑节点先行（截图、输入、进程），配对授权；手机节点跟上 |
| M4 | 语音 + 多媒体 | 轮次式语音（STT → 同一循环 → TTS）；媒体库与播放工具 |

量级参考：业余时间约半年到一年；全职约一到两个月。

## 7. 技术选型

- **pnpm monorepo + TypeScript**：LLM / MCP 生态最全，迭代速度优先；Rust 只出现在 Tauri 壳需要的地方
- **模型接入**：OpenAI 兼容适配层——GLM / OpenAI / Claude / ollama 通吃，换模型只改配置
- **工具协议**：MCP（Model Context Protocol），不自造协议，白嫖生态现成 server
- **UI**：React；壳用 Tauri 2（一套代码同时出桌面端 + 移动端）
- **编辑器三件套（M1 备用）**：CodeMirror 6、xterm.js、diff 视图

## 8. 风险与备忘

- **手机是权限地狱**：iOS 沙盒内能做的有限（快捷指令、通知、剪贴板），安卓宽裕得多；手表最后做，其交互 = 看通知 + 回一句话
- **网络是硬骨头**：手机在外面要够得着家里的大脑（内网穿透 / 中继 / P2P）。v1 只要求同一局域网，v2 加中继，P2P 缓
- **主动性要留接口**：科幻感的一半来自"它主动找我"（通知、定时任务、事件触发）；大脑不能只是一个只会应答的函数
- **API 费用**：编码 agent 跑一晚几块到几十块很正常，影响默认模型选择与"本地小模型兜底"的优先级
- **根 README 已过期**：仍在描述已删除的旧 core（read 工具），动工时重写
