## 1. 本阶段目标（一句话）

把 agent 内核跑起来，让它以**终端形态**出生：能对话、能读写这个仓库、能跑命令，每一步都有权限确认和 git 兜底——最后由它自己完成一次自我修改，作为毕业仪式。

依据：架构文档 D6（出生形态 = 内核 + CLI）。

## 2. 范围

**做**：agent 循环（GLM，OpenAI 兼容端点，流式 + function calling）、read / edit / shell 三个工具、权限确认、会话 JSONL 落盘与续聊、终端 REPL。

**动工前 · 第 0 步（只出文档，不写代码）**：先钉死“手脚”的形状——工具的定义、执行、门禁、结果四条契约，以及四个真工具（read / write_file / edit_file / shell）的参数与错误码。详见 [第 0 步 · 工具契约](./2026-11-03-第0步-工具契约.md)。它不新增任务编号，T4–T7 的实现一律对照它，不再各自发挥。

**不做（推迟表）**：

| 事项 | 推迟到 |
|---|---|
| MCP 协议接入（本阶段用内部工具注册表，接口形状预留） | 暂定 M2，动工时可再议 |
| 记忆卡、多会话管理 | M2 |
| TUI 美化、流式动画 | M1 |
| 桌面壳（Tauri） | M1 |
| 设备控制 | M3 |
| 语音 | M4 |

## 3. 任务分解（按顺序执行，一次只推进一个）

> 尺寸：S ≈ 半天，M ≈ 1 天，L ≈ 2 天。每个任务完成动作：验证通过 → commit → 勾选本清单。
> 协作方式：每个任务按《编码规范与协作约定》的流程走——AI 讲解，核心代码由你写。

- [ ] **T0 · 仓库与脚手架**（S）
  - `git init`；`.gitignore`（`node_modules/`、`.env`、`dist/`）；`.env.example` 模板（API key 不进仓库）
  - pnpm workspace：`packages/kernel`、`packages/tools`、`packages/cli`；根 + 各包 tsconfig；要求 Node ≥ 22.18（原生 TS 类型剥离）
  - 测试用 Node 内置 `node:test`，不引测试框架；每包最小 `index.ts`
  - 重写根 README（项目是什么、当前阶段、如何运行——替换掉描述已删旧 core 的版本）
  - **验收**：`pnpm install` / `pnpm typecheck` / `pnpm -r test` 全绿，首个 commit 落库

- [ ] **T1 · 会话模型（不联网）**（S）
  - `kernel/src/session/`：`message.ts`（Message 类型：system / user / assistant / tool）、`session.ts`（Session：id、messages、append、与 JSONL 互转）
  - 一个会话一个文件，一行一条消息事件
  - **验收**：单测——追加消息 → 落盘 → 重新加载，内容一致

- [ ] **T2 · 模型接入（非流式先通）**（S/M）
  - `kernel/src/provider/`：原生 `fetch` 调 GLM `chat/completions`（OpenAI 兼容）；baseURL / model / key 从 `.env` 读
  - 错误收敛成 `ProviderError`：网络失败 / 401 / 429 各有"下一步怎么办"的提示（错误是教程）
  - **验收**：脚本完成一轮问答；故意改错 key，错误提示能指路

- [ ] **T3 · 流式输出**（S）
  - SSE 增量解析（`data:` 行、`[DONE]`），增量回调
  - cli 侧最朴素逐字打印
  - **验收**：终端逐字出字；Ctrl+C 中断不崩

- [ ] **T4 · 工具循环（本阶段的心脏）**（L）
  - `kernel/src/agent/loop.ts`：模型 → 解析 tool_calls → 执行 → 以 role:"tool" 回喂 → 循环，直到不再调工具；**最大轮数保护**（如 8 轮，超限说明并停止）
  - `tools/src/registry.ts`：Tool 接口（name / description / parameters JSON Schema / execute / riskLevel），完整契约见《第 0 步 · 工具契约》§3
  - 先注册一个假工具 `echo` 做联调
  - **验收**：让模型"用 echo 复述 hello"，日志能看到完整一圈；死循环被轮数保护掐断

- [ ] **T5 · read 工具**（M）
  - `tools/src/read/`：read（一个工具按路径分流——文件：行号前缀、行数/字节双预算截断、`truncated` 自报；目录：v0 只做列表，不做树）
  - 继承旧 core 的设计做减法：错误码体系、"错误是教程"文案、预算红线
  - 权限：低风险，默认放行 + 审计记录
  - **验收**：让它"读 README 并总结"真实调用了 read；喂大文件能截断并自报

- [ ] **T6 · edit 工具 + 确认门禁**（M/L）
  - `kernel/src/permission/`：风险分级（low 自动放行 / high 需确认）；kernel 只发"待确认事件"，**决策权在 cli 层**（内核不碰终端）
  - `tools/src/edit/`：v0 两个原语——write_file（整文件写入）、edit_file（旧串 → 新串唯一匹配替换；匹配 0 处或多处都报错，不猜）
  - cli 确认 UI：先展示文本 diff，y 才执行
  - **验收**：n 拒绝会把"用户拒绝了"作为结果喂回模型、它改道；y 之后 `git diff` 可见改动

- [ ] **T7 · shell 工具**（S/M）
  - `tools/src/shell/`：child_process 执行 + 超时 + 输出截断 + 退出码透传
  - 风险最高：一律确认
  - **验收**：让它跑 `git status`、`pnpm typecheck` 并解释输出

- [ ] **T8 · CLI 组装 + 会话续聊**（M）
  - `cli/src/repl.ts`：readline REPL；可见的工具调用过程（工具名 + 参数摘要 + 等待确认）；最小命令 `/new`、`/exit`；启动参数 `--resume` 接最近会话
  - **验收**：杀掉进程重开，能接着上次对话继续

- [ ] **T9 · 出生演练（毕业考试）**（S）
  - 完整走一遍 §5.2 的验收场景 A → D
  - 通过后：打 tag `v0.1-birth`，出生证明签发

## 4. M0 结束时的代码地图

```
packages/
  kernel/src/
    session/        # Message、Session、JSONL 落盘与恢复
    provider/       # OpenAI 兼容客户端、SSE 解析
    agent/          # 主循环：模型 ↔ 工具 ↔ 确认事件
    permission/     # 风险分级、待确认事件
  tools/src/
    registry.ts     # 工具注册表（Tool 接口的唯一定义处）
    read/           # 读文件 / 读目录
    edit/           # 写文件 / 精确替换
    shell/          # 执行命令
  cli/src/
    repl.ts         # 终端交互、确认 UI
    printer.ts      # 流式打印
```

（符合规范四：文件夹是模块，`index.ts` 唯一出口。）

## 5. 最终成果（Definition of Done）

### 5.1 交付物清单

1. 一个终端 CLI（占位名 `uni`，可改）：仓库根目录 `pnpm uni` 即进入对话；
2. 能力：流式文字对话；read / edit / shell 三个工具；一切写操作与命令执行**先展示、后确认**；会话 JSONL 落盘，重启可续聊；
3. 仓库：分支工作流运转中，每任务一个 commit，结尾 tag `v0.1-birth`；
4. 文档：新版根 README；`docs/` 里一篇**由它自己写的**"出生笔记"；
5. 全程符合《编码规范与协作约定》。

### 5.2 验收场景（最终考试）

- **场景 A · 会读**：新会话，"读一下 docs 目录，总结我们定了哪些决策"——它调用 read 完成，引用准确；
- **场景 B · 会改**："把根 README 里过期的段落改掉"——终端先出 diff，y 后落盘，`git diff` 可见，改动正确；
- **场景 C · 会跑**："跑一下 pnpm typecheck，告诉我结果"——它执行命令、读输出、如实汇报（包括失败也如实说）；
- **场景 D · 会自我更新（毕业项）**："开一个分支，给自己加一个 /help 命令，列出所有支持的命令，然后提交"——全程你只审 diff 和按确认，合并后 `/help` 真实可用。

### 5.3 出生证明（对应架构文档 §5）

- [ ] 能在电脑上用文字与它对话
- [ ] 它能读写本仓库、跑命令
- [ ] 它的每个动作有 git 与权限兜底
- [ ] 它自己开分支，给自己加上了第一个功能

四条全勾 = **M0 关闭，agent 出生**。

### 5.4 规范自查（交付前过一遍）

- [ ] 没有任何模块是一次性生成的（T0–T9 小步可查）
- [ ] 核心逻辑由我本人写出，AI 代写处有标注且我能复述
- [ ] 方法体有编号步骤注释，注释说业务动作
- [ ] 文件夹 = 模块、index.ts 唯一出口、单文件不超两屏
- [ ] 命名见名知意，领域词汇全项目一致

## 6. 节奏与降级预案

- 预估：全职约 1 周，业余约 2–4 周；
- 某任务卡住超过预估两倍时间 → 启用降级，不在原地死磕：read 去掉目录列表只留读文件；edit 只留 write_file；shell 去掉超时。降级不丢人，M0 的唯一目标是**出生**；
- 三个工具之外想加任何工具（glob / grep…）→ 记到 M1 待办，本阶段不加。
